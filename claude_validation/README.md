# 친구의 Claude 모델: 검증 CSV 전용 수정본

첨부된 `261022.zip`의 `main.py`, `eval_val.py`를 검토해 수정한 버전입니다.
친구 모델의 LightGBM L1, 800 trees, 설비용량 × k 가중치, 예측 배율 1.00은 유지했습니다.
원본은 `original/261022/`에 그대로 보관했습니다. 수정본의 실행 진입점은 **make_val.py**입니다.

## 현재 완료 범위

코드 수정과 합성 데이터 검증을 완료했습니다. 첨부 ZIP에는 코드만 있어 **실제 검증 CSV와 실제 점수는 아직 생성하지 못했습니다**.
다음 Parquet 3개가 필요합니다. `sites.csv`는 기존에 받은 파일을 재사용할 수 있습니다.

```text
OIBC2026_dataset/
  sites.csv
  train/
    generation.parquet
    forecast_wa.parquet
    forecast_wb.parquet
    smp.csv                 # CSV 생성에는 불필요, 별도 채점에만 필요
```

`test/` 예보, 평가용 루트 `smp.csv`, 실측 기상 파일은 검증 CSV 생성에 필요하지 않습니다.

## 실행

GitHub 저장소 전체를 내려받은 뒤 저장소 루트에서 실행합니다. Python 3.11 이상을 사용하세요.

```bash
python -m pip install -r requirements.txt
python claude_validation/make_val.py --data OIBC2026_dataset --output val_pred_claude_fixed.csv
```

출력은 **val_pred_claude_fixed.csv 하나**입니다. 모델, 최종 제출용 forecast.csv, composition.csv는 생성하지 않습니다.
이미 같은 파일이 있으면 덮어쓰지 않고 중단합니다. 새 이름을 지정하세요.

- 학습: `2024-06-01 01:00:00+09:00` **미만**인 발전량·예보만 사용합니다.
- 발전소 통계: 위 학습 발전량만 사용합니다.
- 검증: `2024-06-01 01:00:00+09:00`부터 `2025-06-01 00:00:00+09:00`까지 양 끝 포함입니다.
- 예측 입력: `train/forecast_wa.parquet`, `train/forecast_wb.parquet`의 해당 기간 예보입니다.
- 출력: `site_id,ts,kwh` 순서, 253개 × 8,760시간 = **2,216,280행**입니다. 헤더 포함 2,216,281행입니다.
- 시각은 `+09:00`이 붙습니다. 키 중복·누락·범위 밖 시각·음수·NaN·무한대를 검사한 뒤 파일을 확정합니다.
- 검증 기간 발전량은 학습 및 예측 과정에서 읽지 않습니다. 조기종료나 배율 선택에도 사용하지 않습니다.

기본 스레드는 4개, 추론 묶음은 7일입니다. 메모리가 부족하면 추론 묶음을 줄일 수 있습니다.
단, 학습은 학습 기간 특징 행렬 전체를 메모리에 올리므로 이 옵션만으로 학습 메모리가 줄지는 않습니다.
전체 실제 데이터의 실행 시간과 메모리는 아직 측정하지 않았습니다.

```bash
python claude_validation/make_val.py --data OIBC2026_dataset --output val_pred_claude_fixed.csv --threads 4 --chunk-days 2
```

이 분리는 요청하신 **팀 내부 비교 규칙**입니다. 이전 GPT 코드의 실제 하루전 예측용 전일 17시 제한과는 다릅니다.
팀 규칙을 정확히 따라 `2024-06-01 00:00`까지의 학습 자료를 허용합니다.
실제 대회 제출 모델로 전환할 때는 다시 전일 17시 정보 제한을 적용해야 합니다.

## 수정한 사항과 이유

1. **일평균 예보 특징을 라벨 존재 여부에서 분리했습니다.**
   원본은 `generation`에 행이 있는 시간만 골라 그날 운량·강수확률 평균을 계산했습니다.
   같은 발전소·날짜라도 실적 수집 누락에 따라 특징이 달라지고, 전체 시간 격자로 예측할 때와도 계산 기준이 달랐습니다.
   수정본은 해당 대상일에 발행된 예보 전체에서 주간 평균을 계산합니다. 다음 날 00시는 전날의 마지막 구간입니다.
   같은 날 뒤쪽 시간의 예보도 전날 17시까지 발행된 하루전 예보이므로 사용할 수 있습니다.
   추론을 며칠씩 나누어 실행해도 동일한 특징을 사용합니다.

2. **학습·검증·test 데이터 접근을 분리했습니다.**
   원본은 train/test 예보를 먼저 합치고 검증 후 최종 학습·제출 파일 생성까지 계속했습니다.
   이것만으로 원본에 미래 라벨 누수가 있었다고 단정할 수는 없습니다. 실제 통계도 gtr로 계산하고 있었습니다.
   다만 요청 범위를 명확하게 검증하도록 새 실행기는 학습 시점 필터를 강제하고,
   학습 완료 후에만 검증 예보를 읽습니다. 최종 제출용 재학습 단계는 실행하지 않습니다.

3. **시간대 없는 원본 시각을 KST로 해석합니다.**
   데이터 설명은 모든 시각을 KST로 정의합니다. 원본은 naive 시각을 UTC로 간주해 9시간 이동시킬 가능성이 있었습니다.
   이미 시간대가 있는 자료는 그대로 KST로 변환합니다. 예측 CSV는 시간대 표시가 없으면 오류 처리합니다.

4. **무한대 통계와 예보 누락·중복을 처리합니다.**
   오후 평균 발전량이 0일 때 `s_am_ratio`가 무한대가 될 수 있어 NaN으로 바꿉니다.
   B 풍속·돌풍은 km/h에서 m/s로 통일했습니다. 라운드 누락 표시 특징을 추가했고,
   동일 관측지점·라운드·시각 중복은 오류 처리합니다. 다른 라운드로 보완하는 원본 방식은 유지합니다.

5. **잘못된 예측 파일이 조용히 좋은 점수를 얻지 않도록 채점기를 보강했습니다.**
   원본의 중복 행 합산, 누락 예측 0 대체, SMP 없는 시각 제거는 입력 실수를 숨길 수 있었습니다.
   수정본은 기본적으로 완전한 격자와 유효한 값을 요구하고, 채점 시각의 SMP가 없으면 중단합니다.
   비교가 필요할 때만 `--allow-incomplete`로 원본의 누락 예측 0 처리 방식을 선택할 수 있습니다.
   원본 모델 내부 채점은 inner join, 별도 채점기는 left join이어서 누락 시 기준이 달랐습니다.
   수정 채점은 별도 팀 채점기의 left join 기준을 따릅니다.

6. **주 지표 발전소 선정 기준의 설명 오류를 명시했습니다.**
   원본 설명은 ‘2024-04-01 이전’, 실제 계산은 `VAL_FROM - 60일`, 즉 **2024-04-02 01:00 KST 이전**입니다.
   기존 점수와의 비교를 위해 실제 계산식을 유지했습니다. 발전소 수도 174로 고정 출력하지 않고 데이터에서 계산합니다.
   원본의 147.0/136.7백만원 안내 값은 여기서 재현하지 못했으므로 수정본의 성능 근거로 사용하지 않습니다.

## 별도 점수 확인

CSV 생성 후 필요할 때만 아래 명령을 실행합니다. 이 단계는 검증 실적과 `train/smp.csv`를 읽으며 학습에는 영향을 주지 않습니다.

```bash
python claude_validation/eval_val.py val_pred_claude_fixed.csv --data OIBC2026_dataset
```

원래 친구 채점기에도 동일 CSV를 입력할 수 있습니다. 정상 입력의 W, W_G1, W_G2, wWAPE 계산이 같음을 합성 데이터에서 검증했습니다.
원본의 고정 경로 규칙에 맞게 `src/eval_val.py`, `OIBC2026_dataset/`를 배치하면 됩니다.

채점 집합은 `current_group` A→G1, B→G2로 고정합니다.
**실적이 존재하는 발전소·시각만** 합산하는 팀 채점 방식을 유지합니다.
이는 기존 GPT 코드의 ‘모든 발전소 실적이 있는 시각만 채점’과 다르므로 두 보고서의 금액을 직접 비교하면 안 됩니다.
계산식은 W = 0.10 × Σ SMP × k × |집합 예측 - 집합 실적|이며 작을수록 좋습니다.
0으로 나누는 가중오차율과 비어 있는 주 지표 집합은 숫자 0 대신 null로 표시합니다.

## 성능 개선 후보와 검증 상태

현재 변경은 입력 일관성·규칙 준수·재현성 개선입니다. **실제 데이터 점수가 좋아졌다고 확인한 것은 아닙니다.**
가격까지 반영한 `capacity × SMP × k` 가중치, L1/L2 모델 혼합, 학습 구간 내부 시간순 튜닝은 추가 비교 후보입니다.
이 후보들은 이번 수정에 적용하지 않았습니다. 검증 1년 전체를 보고 배율·하이퍼파라미터를 맞추면 팀 비교의 독립성이 떨어집니다.

```bash
python -m pip install pytest==8.3.5
python -m pytest -q claude_validation/tests
```

테스트는 KST 처리, 시간 경계, 검증 라벨 사용 차단, 일평균 특징의 결측 패턴·추론 묶음 독립성,
발전소 통계 무한대, 채점식 원본 일치, 중복·누락·음수 거부, CSV 단독 출력을 검사합니다.
